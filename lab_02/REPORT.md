### 3 Поверхностное и глубокое копирование

Прогноз: append изменит original и alias; замена оценки во вложенном списке изменит также shallow. Глубокая копия сохранит исходные оценки. Фактические состояния приведены в таблице 2.

Внешние id совпадают только у original и alias. Первый вложенный список общий у original, alias и shallow; у deep он другой. Таблица 3 — Свойства способов копирования

| Операция | Новый внешний объект | Новые вложенные объекты | Независимость изменений |
| --- | --- | --- | --- |
| Присваивание | Нет | Нет | Нет |
| Поверхностная копия | Да | Нет | Только состав внешнего списка |
| Глубокая копия | Да | Да для вложенных списков | Да для исследованной структуры |

Прогноз для матриц: умножение внешнего списка повторяет ссылки на одну строку. После wrong_matrix[0][0] = 1 получены три строки [1, 0, 0] с одинаковыми id. В списковом включении каждая строка создается отдельно: correct_matrix равна [[1, 0, 0], [0, 0, 0], [0, 0, 0]], id трех строк различны. Прогноз подтвержден.

Ответы на вопросы. Поверхностная копия создает новый контейнер, сохраняя ссылки на вложенные объекты. Глубокая копия рекурсивно копирует поддерживаемые изменяемые компоненты с учетом уже посещенных объектов. Она требует дополнительных памяти и времени, может копировать излишние данные и не является универсальным способом копирования файлов, сокетов и других ресурсов. Поверхностной копии достаточно при изменении только внешнего контейнера или при неизменяемых элементах.

### 4 Подсчет ссылок и время жизни

Прогноз: alias и помещение data в контейнер увеличат счетчик на 1; del alias и container.clear() уменьшат его на 1. Фактические значения в таблице 4 соответствуют прогнозу.

Таблица 4 — Изменение счетчика ссылок

| Шаг | sys.getrefcount(data) | Изменение |
| --- | --- | --- |
| Создание data | 2 | База |
| Создание alias | 3 | +1 |
| container = [data] | 4 | +1 |
| del alias | 3 | −1 |
| container.clear() | 2 | −1 |

sys.getrefcount получает объект как аргумент, что добавляет временную сильную ссылку на время вызова. Поэтому при одном имени data показано 2. del удаляет привязку имени: объект продолжает жить, если к нему существуют другие сильные ссылки. Для обычного нециклического объекта CPython освобождает объект при падении счетчика до нуля.

Прогноз для слабой ссылки: после del record weak_record() вернет None. Фактически до удаления получен объект Record, после — None. Слабая ссылка позволяет найти объект, пока он жив, но не увеличивает число удерживающих его сильных ссылок. Например, слабый кэш может хранить уже созданные объекты, не мешая их освобождению после закрытия всех использующих их документов.

Прогноз для WeakValueDictionary: ключи a, b, c; после del c — a, b; после del a — только b. Вывод запуска полностью совпал с прогнозом. Для b сохранялась отдельная сильная ссылка, и registry['b'] is b проверено через assert.

Ответы на вопросы. Нулевой счетчик позволяет освободить обычный объект; цикл требует отдельного анализа достижимости. Освобождение Python-объекта не гарантирует немедленный возврат памяти операционной системе: аллокатор может сохранять освобожденные блоки для повторного использования. Сильная ссылка удерживает объект, слабая не управляет его временем жизни.

### memory_report.py

```python
import gc
import sys
import tracemalloc

# Прогноз: список растет ступенями, range занимает меньше памяти.
# Сначала собираем измерения. Печать будет ниже.
rows = []
names = ['empty list', 'list 10', 'tuple 10', 'string 10',
         'int', 'None', 'list 100000', 'range 100000']
for name in names:
    gc.collect()
    tracemalloc.start()
    if name == 'empty list':
        obj = []
    elif name == 'list 10':
        obj = list(range(10))
    elif name == 'tuple 10':
        obj = tuple(range(10))
    elif name == 'string 10':
        obj = 'abcdefghij'
    elif name == 'int':
        obj = 1000
    elif name == 'None':
        obj = None
    elif name == 'list 100000':
        obj = list(range(100000))
    else:
        obj = range(100000)
    current, peak = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    if name == 'int' or name == 'None':
        count = 1
    else:
        count = len(obj)
    rows.append([name, count, sys.getsizeof(obj), current, peak])
    del obj

numbers = []
old_size = sys.getsizeof(numbers)
growth = [[0, old_size]]
for number in range(100):
    numbers.append(number)
    new_size = sys.getsizeof(numbers)
    if new_size != old_size:
        growth.append([len(numbers), new_size])
        old_size = new_size

ratio = rows[6][4] / rows[7][4]

# Измерения закончены. Теперь выводим сохраненные данные.
print('Прогноз: список растет ступенями; range требует меньше памяти.')
print('Сценарий | Элементов | Размер, Б | Текущая, КиБ | Пиковая, КиБ')
for row in rows:
    print(row[0], row[1], row[2], round(row[3] / 1024, 3),
          round(row[4] / 1024, 3), sep=' | ')
print('Рост списка (длина, байт):', growth)
print('Отношение пиков list/range:', round(ratio, 2))
```
